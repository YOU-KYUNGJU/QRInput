## 1. 결론 요약

두 스크립트는 별도 시스템이라기보다 같은 자동화 엔진을 팀별 운영 규칙에 맞게 복제·수정한 형태에 가깝다.

따라서 성능 개선 방향은 다음이 타당하다.

1. 공통 처리 엔진을 먼저 정리한다.
2. 팀별 차이는 설정값과 전처리 규칙으로 분리한다.
3. 병목 제거는 공통 엔진에 한 번 적용하고, 팀별 예외만 따로 관리한다.

## 2. 공통 구조

두 스크립트 모두 아래 구조가 거의 동일하다.

1. 시간대 기준 날짜 폴더 계산
2. 네트워크 경로에서 CSV 목록 수집
3. FITI 실행 및 로그인
4. GUI 생성 후 자동 시작
5. Excel COM으로 CSV 오픈
6. 행 단위 QR 생성 및 `Send`
7. `ControlGetText`와 `PixelGetColor`로 결과 판정
8. 스크린샷 저장 및 로그 기록
9. 완료 후 FITI 종료

공통 병목도 동일하다.

1. `Sleep` 기반 고정 대기 다수
2. QR 재입력/검증 로직 중복
3. Excel COM 셀 단위 반복 접근
4. 픽셀 기반 판정과 화면 의존
5. GDI+ 시작/종료 반복
6. `MsgBox`/`GuiControl` 갱신 과다

6. 완료 후 파일 이동 여부
