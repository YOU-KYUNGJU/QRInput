# QR Input 통합 운영 요구사항 로그

- 작성일: 2026-04-11
- 목적: 사용자와 합의된 운영 정책 및 구현 요구사항 기록

## 1. 대상 시스템

- FITI시험연구원 시험관리시스템 QR 입고 자동화
- 대상 팀:
  - 분석화학평가팀
  - 가공성능평가팀

## 2. 팀별 접수번호 규칙

분석화학평가팀:

- CSV 샘플: `H1.csv`, `H2.csv`
- 생성 규칙: `@ + A열 + D열 + B열 + @`
- 예: `H231,14717,1,26` -> `@H2312614717@`

가공성능평가팀:

- CSV 샘플: `20260410_095128.csv`, `20260410_095205.csv`
- 사용 규칙: `B열 값 그대로 사용`
- 예: `@W2412600042@`
- 실제 운영에서는 `B2`, `B3` 등 여러 행이 채워질 수 있음

공통 규칙:

1. 값이 이미 `@...@` 형식이면 그대로 사용
2. 아니면 팀별 조합 규칙으로 생성
3. 생성 실패 시 로그 남기고 다음 행 진행
4. 가공성능평가팀은 `B열 전체 유효값 스캔` 방식으로 구현

## 3. 운영 정책

1. 두 팀 모두 한 PC에서 순차 로그인 가능
2. 팀 작업 종료 후 FITI시험관리시스템은 완전 종료 가능
3. 실행 시작 전에 기존에 열려 있는 FITI가 있으면 먼저 종료
4. QR 스캔 실패 시 시스템은 멈추지 않고 다음 작업으로 계속 진행
5. 세션 끊김 시 자동 재로그인은 최대 3회
6. 재로그인 3회 실패 시 실패 로그를 남기고 다음 실행 시간까지 대기
7. 실패 행은 최대 3회 재시도 후 다음 행으로 넘어감
8. 실패 건은 다음 실행에서 다시 재시도
9. 완료 파일은 이동하지 않고 원본 위치에 그대로 둠
10. 성공 로그 스크린샷은 전체 저장
11. 성공/실패 로그는 모두 남김
12. 날짜 판정에서 전일 폴더 확인 규칙은 실시간 처리 구조에서는 불필요
13. QR스캔 빨간 체크 박스는 체크/미체크 상태 화면 기준을 확보함
14. 저장 완료 시점에는 별도 특이 화면이나 팝업은 없음

## 3-1. 로그인 화면 정보

1. 로그인 창 제목은 `시험관리시스템 로그인`
2. 기존 스크립트 기준으로 로그인 입력 컨트롤 자동입력 가능
3. 팀별 로그인 ID/비밀번호는 사용자로부터 확보됨
4. 보안상 원문 자격증명은 계획 문서에 직접 기록하지 않고 외부 설정 파일로 분리하는 것을 원칙으로 함
5. 설정 템플릿 파일: `config/qr_input_config.template.ini`

## 4. 스케줄러 현황

현재 작업 스케줄러 `QR입고` 트리거 확인값:

1. 매일 `06:55`
2. 매일 `11:55`
3. 매일 `19:24`

운영 목표:

- CSV 생성 후 `1시간 이내` 반영

## 5. 로그 정책

기본 로그 형식은 `CSV`를 사용한다.

이유:

1. 필터와 집계가 쉬움
2. 팀별 처리량과 실패율 분석 가능
3. 엑셀로 바로 검토 가능

권장 로그:

1. 처리 이력 `CSV`
2. 사람이 읽는 요약 `TXT`는 선택
3. 스크린샷은 성공/실패 모두 저장

## 6. 성능 판단에 필요한 측정 항목

운영 중 아래 항목을 별도 측정 로그로 축적한다.

1. 실행 시각
2. 팀명
3. 대상 CSV 파일 수
4. 파일당 행 수
5. 총 처리 대상 행 수
6. 성공 건수
7. 실패 건수
8. 전체 실행 시간
9. 로그인 소요 시간
10. QR 입력 검증 소요 시간
11. 체크 박스 처리 소요 시간
12. 저장 소요 시간
13. 세션 끊김 횟수
14. 재로그인 횟수
15. 행 재시도 횟수
16. 가장 오래 걸린 단계
17. 비고

## 7. 아직 확보하면 좋은 추가 자료

1. 세션 끊김 또는 로그인 풀림 화면
2. 접수번호 형식에 영문 접두어가 항상 포함되는지 여부
