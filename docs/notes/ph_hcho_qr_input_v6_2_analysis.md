## 1. 현재 시스템 개요

이 스크립트는 pH/폼알데하이드 파트의 QR 입고 자동화를 수행한다.

주요 흐름:

1. 현재 시간대에 따라 네트워크 폴더에서 작업 날짜를 계산한다.
2. 해당 날짜 폴더의 CSV 파일 목록을 수집한다.
3. FITI 프로그램이 없으면 실행 후 로그인한다.
4. GUI를 띄우고 CSV 파일별 작업 상태를 표시한다.
5. 각 CSV 파일을 Excel COM으로 열고 A열 마지막 행까지 반복 처리한다.
6. 각 행에서 접수번호를 조합해 FITI 화면에 `Send`로 입력한다.
7. 화면 텍스트와 픽셀 색상으로 성공 여부를 확인하고, 필요 시 저장 클릭과 스크린샷 로그를 남긴다.
8. 전체 작업 완료 후 FITI를 닫고 스크립트를 종료한다.

## 4. 개발 계획서에 넣기 좋은 개선 과제 초안

### 우선순위 A: 처리 시간 단축

1. `Sleep` 중심 대기를 공통 `WaitForCondition` 함수로 치환
2. QR 입력 검증/재시도 로직을 공통 함수로 통합
3. Excel 데이터를 범위 단위로 읽어 COM 호출 횟수 축소
4. 스크린샷을 실패 케이스 중심으로 축소하거나 비동기 저장 검토

### 우선순위 B: 실패율 감소

1. 픽셀 판정과 컨트롤 판정을 함수화하고 타임아웃/재시도 기준 표준화
2. 창 제목, 컨트롤 존재 여부, 활성 창 상태를 단계별로 검증
3. 종료 전 실패 행 번호, 접수번호, 사유를 구조화 로그로 저장

### 우선순위 C: 유지보수성 개선

1. 날짜 계산, 파일 수집, FITI 로그인, CSV 처리, QR 전송, 저장 확인, 로깅을 함수 단위로 분리
2. 하드코딩된 경로/계정/좌표/색상/타임아웃을 설정값으로 외부화
3. 운영용 로그와 디버그용 로그를 분리

## 6. 현재 코드만 기준으로 본 1차 결론

이 시스템의 성능 문제는 단순히 PC 속도 문제보다는 다음 4가지가 핵심으로 보인다.

1. 고정 대기 시간이 너무 많다.
2. UI/픽셀 기반 확인과 재시도가 중복되어 있다.
3. Excel COM과 화면 캡처를 루프 안에서 자주 호출한다.
4. 한 파일에 모든 책임이 몰려 있어 국소 최적화가 어렵다.

즉, 1차 개선은 알고리즘 고도화보다 `대기 전략`, `중복 제거`, `I/O 호출 수 축소`, `구조 분리`에 집중하는 것이 타당하다.
